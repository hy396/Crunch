# 方案：英雄选择的"本地限制 + 服务端放宽"完整改造

> **统筹文档**：整合英雄选择改造的全部修改点，每个修改点都有"修改前"与"修改后"的完整代码对照，方便回溯。
> **改造目标**：允许多名玩家同时选择同一个英雄（服务端放宽互斥限制），同时本地 UI 仍然对当前玩家自己的选择给出视觉反馈（本地灰显）。

## 背景

项目原本按 5v5 MOBA 模式设计英雄选择逻辑：一局内每个英雄只能被一名玩家选中（服务端强校验），UI 上已被选中的英雄会在所有客户端统一标灰。在项目当前进度（英雄数量较少，不足 5 个）下，这套严格互斥会导致玩家凑不齐开局。

改造后希望实现：**任何玩家都能选择任何英雄，包括已被别人选过的**，本地 UI 只对"自己选过的英雄"标灰作为提醒，不影响其他玩家。

## 改造范围（4 处关键修改）

| 编号 | 文件 | 函数 | 目的 |
|------|------|------|------|
| M1 | `UI/Lobby/LobbyWidget.cpp` | `UpdatePlayerSelectionDisplay` | UI 灰显限制为本地玩家 |
| M2 | `Player/MPlayerState.cpp` | `Server_SetSelectedCharacterDefinition_Implementation` | 放宽客户端发起的"选择"RPC 逻辑 |
| M3 | `Framework/CGameState.cpp` | `SetCharacterSelected` | 放宽 GameState 层的唯一性校验 |
| M4 | `Framework/CGameState.cpp` | `SetCharacterDeselected` | 按 PlayerState 而非 Definition 查找，避免误清别人的选择 |

**四处必须全改**，漏掉任何一处都会导致表现异常：

- 只改 M1 → UI 不灰但服务端拒绝，点击无反应
- 改 M1+M2 → PlayerState 放行了，但 `SetCharacterSelected` 还是会在 GameState 拒绝
- 改 M1+M2+M3 → 玩家 B 能选玩家 A 已选的英雄，但 A 换选新英雄时会把 B 的选择误清空
- 改 M1+M2+M3+M4 → 完整生效 ✓

## M1：UI 灰显限制为本地玩家

**文件**：`Source/Crunch/Private/UI/Lobby/LobbyWidget.cpp`
**函数**：`ULobbyWidget::UpdatePlayerSelectionDisplay`

### 修改前

```cpp
// 更新每个玩家的槽位显示
for (const FPlayerSelection& PlayerSelection : PlayerSelections)
{
    if (!PlayerSelection.IsValid())
        continue;
    // 更新槽位名称显示
    TeamSelectionSlots[PlayerSelection.GetPlayerSlot()]->UpdateSlotInfo(PlayerSelection.GetPlayerNickName());

    // 已选择的角色变成灰色让别人知道不能选了
    if (UCharacterEntryWidget* SelectedEntry = CharacterSelectionTileView->GetEntryWidgetFromItem<UCharacterEntryWidget>(PlayerSelection.GetCharacterDefinition()))
    {
        SelectedEntry->SetSelected(true);
    }

    // 如果是当前玩家，更新角色预览
    if (PlayerSelection.IsForPlayer(GetOwningPlayerState()))
    {
        UpdateCharacterDisplay(PlayerSelection);
    }
}
```

### 修改后

```cpp
// 更新每个玩家的槽位显示
for (const FPlayerSelection& PlayerSelection : PlayerSelections)
{
    if (!PlayerSelection.IsValid())
        continue;
    // 更新槽位名称显示
    TeamSelectionSlots[PlayerSelection.GetPlayerSlot()]->UpdateSlotInfo(PlayerSelection.GetPlayerNickName());

    // 如果是当前玩家，更新角色预览并标灰该英雄
    if (PlayerSelection.IsForPlayer(GetOwningPlayerState()))
    {
        UpdateCharacterDisplay(PlayerSelection);

        // 仅本地玩家自己选中的英雄在本地 UI 中标灰
        if (UCharacterEntryWidget* SelectedEntry = CharacterSelectionTileView->GetEntryWidgetFromItem<UCharacterEntryWidget>(PlayerSelection.GetCharacterDefinition()))
        {
            SelectedEntry->SetSelected(true);
        }
    }
}
```

### 要点

- 把 `SetSelected(true)` 调用**搬进** `IsForPlayer(GetOwningPlayerState())` 判断分支内
- **不能直接注释掉灰显**，否则本地玩家自己也看不到选中反馈

## M2：放宽 MPlayerState 的 Server RPC 校验

**文件**：`Source/Crunch/Private/Player/MPlayerState.cpp`
**函数**：`AMPlayerState::Server_SetSelectedCharacterDefinition_Implementation`

### 修改前

```cpp
void AMPlayerState::Server_SetSelectedCharacterDefinition_Implementation(const UPDA_CharacterDefinition* NewDefinition)
{
    // 安全检查
    if (!CGameState || !NewDefinition) return;

    // 如果角色已被其他玩家选择则退出
    if (CGameState->IsDefinitionSelected(NewDefinition)) return;

    // 如果玩家已有选择，先取消旧选择
    if (PlayerSelection.GetCharacterDefinition())
    {
        CGameState->SetCharacterDeselected(PlayerSelection.GetCharacterDefinition());
    }

    // 更新选择并通知游戏状态
    PlayerSelection.SetCharacterDefinition(NewDefinition);
    CGameState->SetCharacterSelected(this, NewDefinition);
}
```

### 修改后

```cpp
void AMPlayerState::Server_SetSelectedCharacterDefinition_Implementation(const UPDA_CharacterDefinition* NewDefinition)
{
    if (!CGameState || !NewDefinition) return;

    // 去除"唯一性"限制：多名玩家可以选择同一个英雄
    // if (CGameState->IsDefinitionSelected(NewDefinition)) return;

    // 如果玩家之前已选择过英雄，先告知 GameState 取消旧选择
    // 注意：SetCharacterDeselected 的签名在 M4 中改为接受 PlayerState
    if (PlayerSelection.GetCharacterDefinition())
    {
        CGameState->SetCharacterDeselected(this);
    }

    // 更新当前玩家的选择并通知 GameState
    PlayerSelection.SetCharacterDefinition(NewDefinition);
    CGameState->SetCharacterSelected(this, NewDefinition);
}
```

### 要点

- 删除（或注释）`if (CGameState->IsDefinitionSelected(NewDefinition)) return;`
- `SetCharacterDeselected` 的调用改为传 `this`（配合 M4 的签名改动）
- `SetCharacterSelected` 保留，因为它负责更新 `PlayerSelectionArray` 并触发 UI 刷新

## M3：放宽 CGameState::SetCharacterSelected 的唯一性校验

**文件**：`Source/Crunch/Private/Framework/CGameState.cpp`
**函数**：`ACGameState::SetCharacterSelected`

### 问题（槽位不显示英雄头像的真正原因）

这是本次改造最关键的一处。`SetCharacterSelected` 内部**又有一层** `IsDefinitionSelected` 早退判断，导致即使 M2 放行了 `MPlayerState`，调用到这里仍被拦下，`PlayerSelectionArray` 对应条目的 `CharacterDefinition` 根本没更新，槽位当然不显示英雄头像。

### 修改前

```cpp
void ACGameState::SetCharacterSelected(const APlayerState* SelectingPlayer,
    const UPDA_CharacterDefinition* SelectedDefinition)
{
    // 检查角色是否已被选择
    if (IsDefinitionSelected(SelectedDefinition)) return;

    // 查找玩家选择条目
    FPlayerSelection* FoundPlayerSelection = PlayerSelectionArray.FindByPredicate(
        [&](const FPlayerSelection& PlayerSelection)
        {
            return PlayerSelection.IsForPlayer(SelectingPlayer);
        }
    );

    if (FoundPlayerSelection)
    {
        // 更新角色定义
        FoundPlayerSelection->SetCharacterDefinition(SelectedDefinition);
        // 广播更新
        OnPlayerSelectionUpdated.Broadcast(PlayerSelectionArray);
    }
}
```

### 修改后

```cpp
void ACGameState::SetCharacterSelected(const APlayerState* SelectingPlayer,
    const UPDA_CharacterDefinition* SelectedDefinition)
{
    // 去除"唯一性"限制：多名玩家可以选择同一个英雄
    // if (IsDefinitionSelected(SelectedDefinition)) return;

    // 查找玩家选择条目
    FPlayerSelection* FoundPlayerSelection = PlayerSelectionArray.FindByPredicate(
        [&](const FPlayerSelection& PlayerSelection)
        {
            return PlayerSelection.IsForPlayer(SelectingPlayer);
        }
    );

    if (FoundPlayerSelection)
    {
        // 更新角色定义
        FoundPlayerSelection->SetCharacterDefinition(SelectedDefinition);
        // 广播更新
        OnPlayerSelectionUpdated.Broadcast(PlayerSelectionArray);
    }
}
```

### 要点

- 仅删除首行的 `if (IsDefinitionSelected(...)) return;`
- 其余不变

## M4：修正 SetCharacterDeselected 的查找依据

**文件**：`Source/Crunch/Private/Framework/CGameState.cpp`
**函数**：`ACGameState::SetCharacterDeselected`（同时修改 `CGameState.h` 的声明）

### 问题（多人选同英雄时的并发 bug）

原实现按 `CharacterDefinition` 查找要清空的条目。在唯一性限制下这样没问题，但放宽后同一个 `DefinitionToDeselect` 可能对应多个 `PlayerSelection` 条目，`FindByPredicate` 只返回第一个匹配——**可能清错人**。

**典型场景：**
- 玩家 A 选了英雄 X，玩家 B 也选了英雄 X
- 玩家 A 换选英雄 Y，调用 `SetCharacterDeselected(X)` 去取消旧选择
- 按 Definition==X 搜索，第一个匹配可能是 B 的条目 → 把玩家 B 的 CharacterDefinition 置空 ✗

### 修改前

**头文件声明（`CGameState.h`）：**

```cpp
void SetCharacterDeselected(const UPDA_CharacterDefinition* DefinitionToDeselect);
```

**实现（`CGameState.cpp`）：**

```cpp
void ACGameState::SetCharacterDeselected(const UPDA_CharacterDefinition* DefinitionToDeselect)
{
    if (!DefinitionToDeselect) return;

    // 查找对应的角色选择条目
    FPlayerSelection* FoundPlayerSelection = PlayerSelectionArray.FindByPredicate(
        [&](const FPlayerSelection& PlayerSelection)
        {
            return PlayerSelection.GetCharacterDefinition() == DefinitionToDeselect;
        }
    );

    if (FoundPlayerSelection)
    {
        // 置空角色定义
        FoundPlayerSelection->SetCharacterDefinition(nullptr);
        // 广播更新
        OnPlayerSelectionUpdated.Broadcast(PlayerSelectionArray);
    }
}
```

### 修改后

**头文件声明（`CGameState.h`）：**

```cpp
void SetCharacterDeselected(const APlayerState* DeselectingPlayer);
```

**实现（`CGameState.cpp`）：**

```cpp
void ACGameState::SetCharacterDeselected(const APlayerState* DeselectingPlayer)
{
    if (!DeselectingPlayer) return;

    // 按 PlayerState 查找该玩家的条目（而非按 Definition）
    FPlayerSelection* FoundPlayerSelection = PlayerSelectionArray.FindByPredicate(
        [&](const FPlayerSelection& PlayerSelection)
        {
            return PlayerSelection.IsForPlayer(DeselectingPlayer);
        }
    );

    if (FoundPlayerSelection)
    {
        // 置空角色定义
        FoundPlayerSelection->SetCharacterDefinition(nullptr);
        // 广播更新
        OnPlayerSelectionUpdated.Broadcast(PlayerSelectionArray);
    }
}
```

### 要点

- 参数由 `const UPDA_CharacterDefinition*` 改为 `const APlayerState*`
- 查找谓词由 `GetCharacterDefinition() == DefinitionToDeselect` 改为 `IsForPlayer(DeselectingPlayer)`
- 记得同步修改 `CGameState.h` 的函数声明
- `MPlayerState.cpp` 中的调用点（见 M2）已配合改为 `SetCharacterDeselected(this)`

## 可选简化：完全移除 deselect 逻辑

其实在本改造后，连 `SetCharacterDeselected` 都可以不调用。因为 `SetCharacterSelected` 本身就是**覆盖**玩家的 `CharacterDefinition`（`FoundPlayerSelection->SetCharacterDefinition(SelectedDefinition)`），不需要先 deselect 再 select。

### 更简化的 M2 版本

```cpp
void AMPlayerState::Server_SetSelectedCharacterDefinition_Implementation(const UPDA_CharacterDefinition* NewDefinition)
{
    if (!CGameState || !NewDefinition) return;

    PlayerSelection.SetCharacterDefinition(NewDefinition);
    CGameState->SetCharacterSelected(this, NewDefinition);
}
```

如果走这条简化路径：

- 不再调用 `SetCharacterDeselected`
- **M4 可以不做**（函数保留原样，变成死代码，或直接从代码中删除）

**推荐：** 如果你希望代码最清爽，采用"简化 M2 + 删除 SetCharacterDeselected" 组合；如果希望保留更完整的流程（方便将来回到唯一性约束），按 M2+M3+M4 完整改。

## CanStartHeroSelection / CanStartMatch 的兼容性

`CGameState.cpp` 中这两个函数：

```cpp
bool ACGameState::CanStartHeroSelection() const
{
    return PlayerSelectionArray.Num() == PlayerArray.Num();
}

bool ACGameState::CanStartMatch() const
{
    for (const FPlayerSelection& PlayerSelection : PlayerSelectionArray)
    {
        if (PlayerSelection.GetCharacterDefinition() == nullptr)
        {
            return false;
        }
    }
    return true;
}
```

**只检查"所有玩家都选了英雄"，不检查"英雄唯一"**，所以本改造**无需改动它们**，直接兼容。

## 关于同屏出现相同英雄模型

允许多人选同一个英雄后，对局中可能出现相同模型同屏的情况。当前项目已通过**队伍材质差异化**（不同队伍的角色带不同色调）缓解了这一问题，视觉辨识度足够。

## 回滚方式

如需恢复严格互斥：

- **M1**：把灰显代码块移回 `if (PlayerSelection.IsForPlayer(...))` 判断**外部**
- **M2**：恢复 `if (CGameState->IsDefinitionSelected(NewDefinition)) return;`，并把 `SetCharacterDeselected` 的参数改回 Definition
- **M3**：恢复 `if (IsDefinitionSelected(SelectedDefinition)) return;`
- **M4**：恢复按 Definition 查找的版本和头文件签名

建议回滚时四处同时操作。

## 改动与项目其他部分的关系

- **对局生成**（`CGameMode::SpawnDefaultPawnFor_Implementation`）：按 `UPDA_CharacterDefinition` 生成角色，不依赖唯一性，**无影响**
- **角色预览**（`LobbyWidget::UpdateCharacterDisplay`）：只更新本地预览，**无影响**
- **聊天、击杀等系统**：不依赖英雄唯一性，**无影响**
- **材质差异化**：开发者已另行实施，和本方案正交叠加

## 预期行为

- 任意数量玩家（≥2）都能开局，不受英雄数量限制
- 本地玩家选中的英雄会在自己 UI 中灰显，其他玩家不受影响
- 所有玩家的大厅槽位都能显示各自选中的英雄头像（包括重复英雄）
- 对局进入顺畅，答辩演示 1v1 / 2v2 / 3v3 均可
